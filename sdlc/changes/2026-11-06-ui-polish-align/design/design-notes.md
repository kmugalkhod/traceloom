# Design notes: UI polish and alignment pass (D-1)

## Direction
Keep the approved v3.1 look (neutral SaaS dashboard, near-black primary, hairline borders) and make it precise: one control height, one row height, one empty state, one page header, and numbers that line up. Nothing is re-themed; the mockup shows only the rules from FR-S1..S8 applied to the real screens.

## Files
- `design/mockup.html`: one self-contained page (Google Fonts only). Theme toggle top right. Tokens in `:root` are DESIGN.md's; the four new size tokens are marked `v3.2`. Mobile frames are 390px wide and scoped under `.m`; in the product use `@media (max-width: 760px)`.
- `DESIGN.md`: now v3.2, with the section "v3.2 alignment pass" (the content T-4 needs).

## Screens (mockup section)
1 Shared rules (control row, states, table, error row, empty, context bars, page header, chart axis) · 2 Traces list (+ loading, empty) · 3 Trace workspace (full-height, working Preview/Metadata/Scores/Comments tabs, tags Member and Viewer, menu, loading) · 4 Dashboard (+ empty) · 5 Sessions and users · 6 Prompts empty and new prompt (validation) · 7 Playground (no connection, with connection) · 8 Settings (menu open, empty list) · 9 Auth (error state) · 10 Mobile 390: traces, trace workspace (stacked), dashboard, prompts, settings, login · 11 Dark.

## Components and tokens
New: `--row-h 44`, `--ctl-h 36`, `--ctl-h-sm 30`, `--panel-head-h 52`. Components to add or rework: `.seg` (36px tray, 30px segments), `.tbl` (44px rows, `.r`/`.c` alignment, `.err` marker only), `.stat` (112px with `.chipi`), `.empty`, `.mline` (inline metrics row), `.split` (full-height panes), `.dpane` (detail tabs), `.mrow`, `.trow` (grid `1fr 72px 72px`), `.io`, `.grid-12`, `.brk`, `.stabs`, `.crumbs` in `.ctxbar`, `.chip.add` and `.chip.add-open`. No new colours, fonts, radii or shadows.

## Interactions
Trays and tabs toggle `aria-pressed` / `aria-selected` (tabs keep their roving-tabindex behaviour from app.js). "+ Add tag" is a real form: without JS it renders the field and an Add button using the existing endpoint; with JS the chip opens the field and focuses it. Tag x buttons are the existing remove forms. "..." menus unchanged. Skeleton shimmer stops under `prefers-reduced-motion`.

## Accessibility
Focus ring 2px `--focus` with 2px offset on everything. Breadcrumb is one `nav[aria-label=Breadcrumb]` in the context bar and is `display:none` on mobile (no hidden duplicate). Error rows keep marker plus Error pill, so status is never colour alone. Copy and menu buttons keep their accessible names. Contrast comes from the existing tokens (text >= 4.5:1, controls >= 3:1). DOM order matches visual order.

## Assumptions (no human could be asked)
1. The chart in the mockup is an illustrative SVG; the real chart keeps its data and only its axis text changes.
2. "Traces" count and Cost per user exist in the top-users query (FR-D5); if Traces does not, drop that column.
3. The Tokens stat caption "in · out" uses data the page already has; if not, show the total only.
4. Mockup frames are about 1230px wide, so the 40/60 split looks tighter than at 1440px (the tree needs its 360px minimum here).
5. Tag add field: Enter submits; Escape closes it and returns focus to "+ Add tag".
6. The mobile settings table is shown as two-line rows (already in DESIGN.md v3.1).
7. Revision 2 (owner): trace detail redesigned as a workspace; sidebar order kept as today (Dashboard, Traces, Sessions, Users / Prompts, Playground / Settings, Shortcuts); the Slow filter and all vs-previous deltas removed; the Scores Type select no longer clips.
8. The mockup's workspace frame is 900px tall to stand for a 1440x900 viewport; the product uses `height: calc(100vh - ...)` on the main area with `min-height: 0` on panes.
9. The impeccable skill was not loaded in this run (time budget); I applied its checks by hand: hierarchy, real copy, every state, contrast via existing tokens, one render check in light and dark with no console errors.
